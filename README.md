# Cloud shape calculator

Open [index.html](./index.html) in a browser. No build step is needed. Run `node test.js` for the sizing and pricing-display checks. The UI follows the supplied Oracle “We are One” PowerPoint template: Georgia headings, Oracle Sans body text, charcoal and off-white surfaces, and Oracle red and gold accents. The Oracle wordmark in `assets/oracle-logo.svg` was extracted from that template. The three-panel layout puts editable shape, region, and capacity inputs on the left; the OCI shape and hourly/monthly estimate in the middle; and Google Cloud custom and standard price options on the right. The user can enter OCI E6 Ax or X12 Ax OCPUs, memory, boot volume capacity, and an optional additional block volume. The initial size and the small, medium, and large presets use a default OCPU-to-memory ratio of 1:6 (6 GB per OCPU); users can edit either input afterward.

The tool treats one x86 OCI OCPU as one core with two threads and uses `2 × OCPUs` as a public Google Cloud Compute Engine vCPU capacity target. It groups predefined single-VM C4D and C4 configurations separately from custom N4 and N4D configurations that meet both CPU and memory requirements, ordered by extra vCPUs and then extra memory. The custom result uses Google’s allowed vCPU steps and 256 MiB memory increments, so it marks an exact vCPU and memory match when the selected series supports one. C4 and C4D are predefined only. N4D custom is offered in Frankfurt, London, Netherlands, and Belgium among the selected regions; the current Google zone list does not list it in the other selected regions. C4D is also filtered by region availability. It does not infer equal workload performance. The OCI processor is AMD EPYC 9J45 for E6 Ax and Intel Xeon 6 6987P-C for X12 Ax. Compute Engine C4D uses AMD EPYC 9B45 (Turin). C4 with 144 or 288 vCPUs uses Intel Xeon Platinum 6985P-C (Granite Rapids); other listed C4 sizes can use Intel Xeon Platinum 8581C (Emerald Rapids) or 6985P-C (Granite Rapids), depending on zone and CPU platform selection.

The OCI monthly total shows its percentage savings against a Google Cloud custom shape with exactly the target vCPUs and memory, and against the closest predefined standard shape when that option is shown. When both comparison types are selected, it shows both percentages. If multiple priced exact custom shapes exist, it uses the least expensive one, giving a conservative OCI savings estimate. The percentage is `(GCP total − OCI total) / GCP total × 100` using unrounded monthly totals; if OCI costs more, the UI says “higher.” If an exact custom shape has no published price, the UI requests a quote instead of showing a percentage.

For the AMD E6 Ax comparison, Oracle publishes 2.7 GHz base and 4.1 GHz maximum boost for EPYC 9J45; Google publishes the same base and maximum boost frequencies for EPYC 9B45, plus a 3.5 GHz effective frequency. The calculator therefore makes no per-core performance ranking from the CPU names or clock figures.

When comparing X12 Ax with Intel Compute Engine shapes, result cards warn that custom N4 uses a different CPU generation (Emerald Rapids) and that C4 sizes other than 144 and 288 vCPUs may run on Emerald Rapids unless Granite Rapids is selected in an eligible zone. This warning appears even for an exact vCPU and memory capacity match.

Hourly and monthly USD estimates use Linux on-demand compute plus Balanced block storage; monthly totals use 730 hours. The Google Cloud region selector covers Frankfurt, London, Paris, Netherlands, Belgium, Milan, Turin, Hamina (Finland), Stockholm, Doha, Dammam, Tel Aviv, and Johannesburg. Google’s public Compute Engine region list does not include the UAE or Kenya, so neither is presented as a deployable region. Region-specific matches are limited to the machine series listed by Google for that location. Oracle uses global USD list prices. Google Cloud predefined VM estimates extrapolate from published 32-vCPU on-demand prices for each class, adjusted using regional 32-vCPU high-memory references. N4/N4D custom compute uses Google’s published Iowa per-vCPU and per-GiB on-demand rates, adjusted with the same corresponding Intel/AMD regional factor; this regional custom rate is therefore an estimate. N4 extended memory uses Google’s published Iowa premium rate. N4D extended-memory shapes are shown as exact capacity matches where possible, but do not show a total hourly price because Google’s public VM pricing table does not list their extended-memory rate. Regional Hyperdisk Balanced capacity rates are estimates. Monthly block-storage prices are divided by 730 hours. Taxes, egress, snapshots, software licenses, discounts, and provisioned disk performance above the included baseline are excluded. Verify rates, capacity, and machine availability in the chosen region before purchasing.
